## 修复：节点上传分批（openspec 变更，未提交）

**根因**：清空快照后暴露真正的故障——节点把 304 篇全文塞进**单个 PUT 请求**，被公网 Hub 前置的 `nginx/1.26.3` 拦下（`client_max_body_size` 默认 1m）：

```
📤 Uploading: 304 full-text, 0 hash-only, 0 deletions
⚠️ Document upload rejected (413): 413 Request Entity Too Large
```

hash-only 轮次不含正文所以碰不到这个限制，**首次接入大知识库才暴露**——而首次接入恰恰最需要成功。

**方案**：节点侧切批（用户拍板，优于调 nginx —— 治本、不依赖部署方配置）。
变更目录 `openspec/changes/2026-09-30-fix-node-upload-batching/`，改 `multi-node-sync` 的 `Node Document Upload` requirement（MODIFIED，8 个原场景全抄 + 新增 4 个）。

**实现要点**：

- `config.py`：新增 `upload_batch_bytes`（默认 512 KiB）与 `upload_batch_docs`（默认 50），`<= 0` 表示该维度不限（逃生舱）
- `sync.py`：新增 `batch_payload()`（切分）、`_doc_entry()`（体积估算，按 UTF-8 字节不按字符）、`_upload_batches()`（串行发送 + 汇总）、`merge_stats()`（跨批求和）
- **关键设计**：`deletions` 仅随最后一批（前序批次带空列表，因为 Hub 见"列表缺失"会按旧语义推导删除）；**任一批失败即整体失败、快照不动**（已成功批次不回滚，靠 `(node_id, path)+hash` 幂等）
- 单篇超限独占一批，保证算法每轮至少推进一个条目（不死循环）

**验证**：

- 节点单测 **149 passed**（基线 129，新增 20）
- 实机端到端（公网 Hub）：`Uploading: 304 full-text ... in 12 batches` → `Synced 304 documents: created=304 ... rejected=0`，Hub 侧独立核对 **304 == 304**
- 服务端测试在本机跑不动（收集阶段挂起，`import app.main` 都无输出），判为**本机环境问题**，本次未改 `src/server` 任何文件

**根因（本次修的代码缺陷）**：`src/node/app/state.py::resolve_snapshot_path` 优先用**包内** `data/sync_state.json`，
导致只要在开发仓跑过一次节点，`AKM_NODE_STATE_DIR` 就永久失效——多环境隔离静默失败。
安装版（`uv tool`）因 `BASE_DIR` 落在 `site-packages` 而**恰好**避开，但不能依赖这个巧合。

**实现**：`config.py` 新增 `USER_STATE_DIR_EXPLICIT = "AKM_NODE_STATE_DIR" in os.environ`；
`resolve_snapshot_path(..., explicit=False)` 显式时直接返回 `user_path`，未显式时行为逐字不变。
判定口径是「环境变量是否存在」而非「是否等于默认值」。

**关键环境事实（易踩坑）**：`AKM_NODE_ENV_FILE` / `AKM_NODE_STATE_DIR` 由 `config.py` 在**模块 import 时**
用 `os.environ` 读取，**早于** pydantic-settings 加载 `.env` —— **写进 `.env` 不生效且不报错**。
必须有启动脚本在进程环境里设置。

### 本轮踩到的两个 Windows 硬事实（重要，已沉淀进 akm-node-ops skill §2.1）

1. **`.ps1` 必须存为 UTF-8 BOM**。PowerShell 5.1 读**无 BOM** 文件按系统 ANSI(GBK) 解码，
   中文注释被误解码 → **解析失败且零输出**（排查了很久）。仓库既有 `deploy/install-akm-node.ps1`
   就是带 BOM 的，可作为约定佐证。反向：`.sh` **不能**有 BOM（破坏 shebang）。
   检查：`head -c 3 x.ps1 | od -An -tx1` → `ef bb bf`。
2. **本机 PowerShell 执行策略是 `Restricted`**（`Get-ExecutionPolicy` 生效值），任何 `.ps1` 都报
   `PSSecurityException: 在此系统上禁止运行脚本` → **无法在会话内实跑 `.ps1` 验证**。
   只能：`Parser::ParseFile` 语法检查（不需执行权限）+ 内联复现逻辑 + 用 `.sh` 版做端到端验证。
3. **PowerShell 工具的 stdout 在本机不回传**（`Write-Host` 也拿不到），只有 `Out-File` /
   `Add-Content` 落盘后用 Read 读才可靠；`Start-Process -RedirectStandardOutput` 同样拿不到。
   另外 **Bash 工具禁止调 PowerShell**（"bypasses PowerShell security checks"）。
   → 以后写 Windows 脚本验证，直接用"脚本自己写日志文件"的路子，别在输出捕获上耗时间。
