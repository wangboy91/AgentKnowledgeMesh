## 启动 akm-node 连接公网 Hub（起于用户请求）

**背景与配置澄清**：用户要求"基于这个项目启动 akm-node 节点"。排查中发现两个配置层次：

- `src/node/.env`（开发仓）：Hub = `https://gotitos.club/akm`，含 `AKM_HUB_USERNAME/PASSWORD`
- `~/.akm-node/.env`（用户级）：旧的内网 Hub `192.168.0.200:8000` + 旧 node 凭证

`config.py` 的 `env_file` 解析顺序是 `[BASE_DIR/.env, USER_ENV_FILE]`，**用户级覆盖开发仓**。用户选择改连公网 Hub，故清空用户级 `.env`（保留注释，备份 `.env.bak-20260930-160922`）。

**踩坑记录**：

1. `src/node/.env` 里 `AKM_HUB_URL=ws:https://gotitos.club/akm/ws` 是笔误，正确应为 `wss://...`（已修正）
2. 启动报 `ImportError: cannot import name 'is_watchable_markdown' from 'akm_shared.scanner'` —— venv 内装的 `akm-shared` 是旧版。原因是 path 依赖版本号没变（都是 0.2.0），uv 不认为需要重装。**解法：`uv sync --reinstall-package akm-shared`**（会更新 `uv.lock`）
3. `~/.akm-node/sync_state.json` 是内网 Hub 时代留下的快照。换 Hub 后节点误判"304 篇都没变"，只发 hash-only → Hub 全判 `rejected (hash mismatch)`。**解法：清空快照为 `{}`** 触发全量
4. **Windows 输出缓冲坑**：`uv run akm-node > file 2>&1 &` 会零输出（Python stdout 重定向到文件是块缓冲，banner 太小刷不出来）。**观察输出的正确姿势：`./.venv/Scripts/python.exe -u -m app`（`-u` 无缓冲）**。另外用 `(&)` 子 shell 后台起的进程会被工具会话回收，须用 `run_in_background=true`

## 修复：节点上传分批（openspec 变更，未提交）

**根因**：清空快照后暴露真正的故障——节点把 304 篇全文塞进**单个 PUT 请求**，被公网 Hub 前置的 `nginx/1.26.3` 拦下（`client_max_body_size` 默认 1m）：

```
📤 Uploading: 304 full-text, 0 hash-only, 0 deletions
⚠️ Document upload rejected (413): 413 Request Entity Too Large
```

hash-only 轮次不含正文所以碰不到这个限制，**首次接入大知识库才暴露**——而首次接入恰恰最需要成功。

**方案**：节点侧切批（用户拍板，优于调 nginx —— 治本、不依赖部署方配置）。
变更目录 `openspec/changes/2026-09-30-fix-node-upload-batching/`，改 `multi-node-sync` 的 `Node Document Upload` requirement（MODIFIED，8 个原场景全抄 + 新增 4 个）。

**实现要点**：

- `config.py`：新增 `upload_batch_bytes`（默认 512 KiB）与 `upload_batch_docs`（默认 50），`<= 0` 表示该维度不限（逃生舱）
- `sync.py`：新增 `batch_payload()`（切分）、`_doc_entry()`（体积估算，按 UTF-8 字节不按字符）、`_upload_batches()`（串行发送 + 汇总）、`merge_stats()`（跨批求和）
- **关键设计**：`deletions` 仅随最后一批（前序批次带空列表，因为 Hub 见"列表缺失"会按旧语义推导删除）；**任一批失败即整体失败、快照不动**（已成功批次不回滚，靠 `(node_id, path)+hash` 幂等）
- 单篇超限独占一批，保证算法每轮至少推进一个条目（不死循环）

**验证**：

- 节点单测 **149 passed**（基线 129，新增 20）
- 实机端到端（公网 Hub）：`Uploading: 304 full-text ... in 12 batches` → `Synced 304 documents: created=304 ... rejected=0`，Hub 侧独立核对 **304 == 304**
- 服务端测试在本机跑不动（收集阶段挂起，`import app.main` 都无输出），判为**本机环境问题**，本次未改 `src/server` 任何文件
