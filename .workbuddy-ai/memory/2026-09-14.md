  扫描仍保留在无文档空态按钮 & Dashboard 页
- 新增 i18n `common.refresh`

### 关键排查:用户"改动没生效"的真正原因
- 现象:用户反馈布局没变。实际源码改动都在,是**访问的 dev server 在跑旧代码/已损坏**(端口 5173 返回 502)
- 排查手法:
  1. `grep` 确认源码已是新版(排除"没改成功")
  2. `curl -s http://localhost:5173/src/components/FileTree.tsx | grep tree-toolbar__row` → 判断 server 实际吐出的模块
  3. `netstat -ano | grep LISTENING | grep :5173` 找 PID
  4. Windows 下 `taskkill //PID` 在 Git Bash 里会报"无效参数";改用 PowerShell `Stop-Process -Id <pid> -Force`
  5. 重启 `npm run dev`,再 curl 校验 200 + 模块含新标识
- **教训:用户说"没生效"时,先确认"源码 vs 运行态"是否一致,别急着重改代码**

### Playwright 截图脚本的 mock 匹配坑(再次踩到)
- 写死 `http://127.0.0.1:5173/api/**` 时,若页面用 `http://localhost:5173` 访问,
  Windows 上 localhost 可能解析到 `::1`,请求不被拦截 → 打到未启动的后端 → 401 → 被踢回登录页
- 正解:用**路径判断函数**而非 host 匹配:
  `page.route((url) => url.pathname.startsWith('/api/'), handler)`
  这样既不受 host 影响,也不会误伤 `/src/api/client.ts`(其 pathname 不以 `/api/` 开头)

## 2026-09-14 追加 · 新增 Token 彻底删除(purge)能力 + 澄清两套凭证

### 需求
用户要求增加"删除功能"(而非只隐藏),并追问 node 重登是否记录、Hub/Node 如何认证。

### 关键澄清:两套独立凭证(易混淆)
1. **API Token** → 表 `api_tokens`,给外部 agent/脚本调 Context API / MCP;软删除(revoke 置 revoked_at)
2. **Node Token** → 表 `nodes.token`(String(64), uuid4().hex),给节点机推文档;
   - `POST /api/nodes/register` 需 **admin JWT**(先 `/auth/login` 拿),每次注册**轮换** token
   - `akm-node login` 若本地 `.env` 已有 `AKM_NODE_ID` 则携带它 → Hub **复用同一节点记录**并轮换 token(不新建)
   - 节点侧持 `AKM_NODE_TOKEN`,`Authorization: Bearer <node_token>`;Hub 在 `PUT /nodes/{id}/documents` 比对 `nodes.token`
   - 实测:远程库 nodes 表 1 条 `DESKTOP-40KK5KK`,created 9-10、updated 9-14(当天),status=online → 重登确实复用+轮换
- 结论:node 重登**有记录**,只是在 nodes 表而非 api_tokens;两者不要混为一谈

### 实现
- 后端:
  - `app/services/api_tokens.py` 新增 `purge_token()`:硬删除;**仅允许删已吊销**(活跃的抛 ValueError,强制先吊销)
  - `app/api/auth.py` 新增 `DELETE /api/auth/tokens/{id}/purge`(admin),400=活跃不可删,404=不存在
  - `tests/test_auth.py` 新增 4 个用例(revoke 软删/幂等、purge 删行、purge 拒绝活跃、purge 不存在)→ 16 passed
  - `docs/api-reference.md` 第 12 行补"彻底删除"
- 前端:
  - `api/client.ts` 新增 `purgeApiToken(id)`
  - `Settings.tsx` 操作列:活跃 → BanIcon(吊销);已吊销 → TrashIcon(彻底删除,二次 confirm)
  - i18n 新增 `settings.purge` / `purgeConfirm` / `purgedToast`

### 注意
- 用户问"你直接删除了吗"——**没有**。排查只用只读 SELECT;临时脚本 `_q_tokens.py` / `_q_nodes.py` 用完即删
- 远程库破坏性操作必须先征得用户同意

### 待澄清(用户提问)
「轮换 token 后应该产生新的有效 token,而不是还是已吊销?是不是没有闭环?」
